# 실행 계획 — 2026-11-13

## 1. 요건과 선택
- [x] 공식 대회 및 신청 안내를 검토하고 기한·유입 조건을 기록한다.
- [ ] 참가 요건과 API 사용 권한, 상세 측정 조건을 확인한다.
- [ ] 사용자 문제·후보 3개 이상·선행 사례·반론을 비교해 주제를 정한다. Codex 직접 조사 결과와 선행 사례를 독립적으로 확인한다.

## 2. 실행 가능성
- [ ] 사용자가 입력하는 정보와 응답 필드를 명세한다. 가격·거리·영업 여부 등 데이터가 없으면 제공한다고 약속하지 않는다.
- [ ] 권리 문제가 없는 가상 데이터로 UI와 사용자 흐름을 검증하고, 실 API는 권한 확인 뒤 최소 호출한다.
- [ ] AI를 별도로 구현해야 한다고 가정하지 않는다. 필요한 경우 사용자 가치와 공식 필수 요건을 확인하고 오류·비용·장애 시 동작을 결정한다. 기술 스택, 비용, 도메인은 아직 미정이다.

## 3. MVP와 검증
- [ ] 식사 조건 입력 → 근거 있는 결과 → 잇플 상세 이동을 구현한다. 다인 실시간 투표 등은 검증 후 판단한다.
- [ ] 모바일·키보드·오류·빈 결과와 API 실패를 검증한다. 로그인이나 서버가 필요한지 데이터와 흐름으로 판단한다.
- [ ] 정식 운영 환경과 등록 도메인에서 실제 브라우저 링크 및 집계 확인. 테스트 유입을 실사용 성과로 해석하지 않는다.

## 4. 제출
- [ ] 서명·제출 서류, 서비스 설명, 도메인, 필요 증빙을 준비한다. 사용자가 신청하고 접수 회신을 확인한다.
- [ ] 대회 종료 뒤 확정 수치와 지급 조건을 확인한다.

일정은 공식 마감과 운영 여건에 따라 변경한다. 미검증 사항은 docs/BLOCKERS.md에서 관리한다.
