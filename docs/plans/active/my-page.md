## 완료 기준 (ui-evaluator·design-auditor가 그대로 판정)

1. 390/768/1440px에서 가로 스크롤 없음, 글자 잘림 없음.

8. 예시 데이터임을 화면에 밝힌다. 예시 후기에는 잇플 링크를 붙이지 않는다(가짜 merUrl 금지).

## 백엔드 연결 전 계약 초안 (2026-11-24, 미구현)
- 현재 `schema.ts`는 비어 있고 `/my`는 예시 데이터·비로그인 고정이다. `MyPageData`는 테이블 행이 아니라 profiles, regions, foods, reviews와 restaurants를 합친 화면 DTO다.
- 후속 API 설계에서 프로필·내 후기 조회, 페이지네이션, 인증 실패·빈 상태·오류, 공유 생성·조회 계약을 정한다. 기존 `/me/territories`·`/me/collection` 초안과 함께 API 응답을 명시적으로 DTO로 변환한다.
- NestJS에서 인증과 user_id 소유권을 직접 확인한다. postgres 계정 연결은 RLS만으로 본인 데이터를 보호하지 못한다. 프론트가 보낸 user_id를 신뢰하지 않는다.
- 프로필 단위 공개 설정은 ERD에 없다. 계정 구분 없는 현재 localStorage나 홈 URL만 공유하는 버튼을 실제 설정·공유에 재사용하지 않는다. 권한·공유 범위 계약 및 저장 모델을 결정한 뒤 연결한다.
- 잇플 데이터 보관 허용 여부가 정해지기 전 응답 저장을 전제하지 않는다. 현재 로그인 예시는 실제 인증 검증이 아니다.
- 유리·정렬 재설계 최종: 비로그인/로그인 예시 × 모바일/PC 독립 시각 평가 모두 8.3. 중간 평가 PC 7.9/7.5 및 7.8 지적 후 전체 두 열의 상단 배치를 수정. /tmp/eats-final-independent/{my,my-preview}-{390,1440}.png.
