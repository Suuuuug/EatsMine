# 잇플 아이디어 정리

최근 유행한 지도 놀이, 게임, 데이터 비교 방식을 맛집 찾기랑 연결해 봄. 식당을 찾는 과정이 재밌으면서도 실제로 오늘 먹을 곳을 고르는 데 도움이 되는 방향으로 생각해 봄.

## 1. 우리 동네 식당 영토전

학교나 직장 주변을 몇 개 구역으로 나누고, 각 구역의 식당을 찾아보면서 내 지도를 채우는 방식임. 예를 들어 신촌을 6개 구역으로 나누고 ‘이번 주에는 아직 안 가본 3번 구역에서 밥 먹기’ 같은 식으로 진행하면 됨.

식당을 검색해 잇플 상세를 보고, 나중에 실제로 먹었다면 사용자가 직접 ‘다녀옴’을 누를 수 있음. 친구들끼리 각자 어느 구역을 채웠는지 비교하거나 강아지 팀·고양이 팀으로 나눠서 경쟁하는 것도 가능함.

**재밌는 점:** 매번 가던 길에서 조금 벗어나게 만드는 이유가 생김. 지도에 각자 채운 흔적이 보이는 것도 재미있을 듯.

**먼저 만들 것:** 한 동네 지도, 업종별 식당 검색, 내 구역 직접 표시. 팀 대전은 그다음.

**생각할 점:** 식당을 열어본 것과 실제 방문은 다르고, 직접 누른 기록만으로 방문이나 결제를 인증할 수는 없음. 지도 채우기만 재밌고 식당 선택으로 안 이어질 수도 있음.

참고로 실제 지역을 돌아다니며 지도를 밝히고 식당을 찾는 [Sidequest](https://apps.apple.com/ca/app/sidequest-explore-your-city/id6759741994) 같은 서비스도 이미 있음. 우리 쪽은 한 동네에서 식당을 고르고, 이후 친구들과 구역을 비교하는 경험에 초점을 맞추는 게 차이점이 될 듯.

## 2. 메뉴 도감 + 계절 한정 퀘스트

포켓몬 도감처럼 음식을 모으는 지도. 예를 들어 국밥 도감에 순대국밥·돼지국밥이 있고, 하나를 누르면 동네와 관련 업종을 골라 식당을 찾아보는 방식임. 직접 먹은 메뉴를 체크하면 도감이 채워지고 동네 지도에도 표시됨.

여기에 매달 제철 식재료 페이지를 붙이는 것도 괜찮을 듯함. 예를 들어 [농촌진흥청의 이달의 식재료](https://www.nongsaro.go.kr/mfood/kfi/foodMonth/list?dtlCode=3&menuId=PS03924&month=11&tabCode=1)를 보고 관련 음식을 정한 다음, 그 음식이 있을 법한 업종을 찾는 식. 캐릭터가 ‘이번 달 탐험대’ 안내를 하는 것도 괜찮을 듯함.

**재밌는 점:** ‘뭐 먹지?’를 ‘이번엔 어떤 음식을 채워볼까?’로 바꿀 수 있음. 계절이 바뀌면 다시 볼 이유도 생김.

**먼저 만들 것:** 음식 10개 정도의 도감, 지역·업종 검색, 사용자가 직접 체크하는 기능.

**생각할 점:** 잇플 업종 검색만으로 특정 메뉴를 판다고 확정할 수는 없음. 관련 식당 후보로 보여주고 실제 메뉴와 제철 재료 사용 여부는 따로 확인해야 함. 음식 도감과 식당 지도를 결합한 [Cibo](https://devpost.com/software/cibo-otdzbr)라는 프로젝트도 있어서 도감만으로는 차별화가 어려움.

## 3. 동네 탐험 빙고

지도 전체를 차지하는 대신, **오늘 한 끼로 깰 수 있는 빙고판**을 주는 방식임. 예를 들면 `아직 안 가본 구역`, `평소 안 고르는 업종`, `이번 달 관심 음식` 같은 칸을 정해두고, 사용자가 한 칸을 누르면 그 조건에 맞춰 식당 검색으로 넘어감.

예시로 ‘안 가본 구역’을 누르면 사용자가 지도에서 직접 골라둔 구역의 업종별 식당 목록을 보여줌. 먹고 나서 직접 완료 표시를 하면 한 칸이 채워짐. 빙고를 완성하기 위해 추가로 식당을 찾아갈 필요는 없음.

**재밌는 점:** 영토전보다 시작이 쉽고, 매번 새로운 동네·업종을 고를 계기가 생김. 친구와 같은 빙고판을 쓰면 서로 다른 선택을 비교할 수도 있음.

**먼저 만들 것:** 3×3 빙고판 한 장, 수동으로 고른 지역과 업종, 잇플 검색, 직접 완료 표시.

**생각할 점:** 빙고가 식당을 찾는 데 도움 되는지 확인해야 함. `조용한 식당`처럼 확인할 수 없는 조건이나 결제해야만 채워지는 칸은 넣지 않는 편이 좋겠음.

## 4. 동네의 두 얼굴

같은 동네의 식당을 **전국 기준과 해당 지역 기준**으로 나란히 보는 비교 서비스임. 동네와 업종을 검색하면 각 가게에서 제공되는 최근 1개월 BC카드 결제 매출의 전국·지역 상위 백분위를 보여줌. 숫자를 보고 궁금한 곳을 골라 잇플 상세로 이동함.

예를 들어 가상의 A 식당이 전국 상위 20%, 지역 상위 5%라면 두 숫자를 그대로 나란히 보여주고, 사용자가 직접 판단하도록 함. 비교 기준이나 응답이 빠진 가게는 `정보 없음`으로 표시함.

**재밌는 점:** 사진보다 숫자와 근거를 먼저 보는 ‘반 인스타 감성’에 가장 가까움. 같은 동네에서도 기준에 따라 숫자가 어떻게 다른지 살펴보는 재미가 있을 듯.

**먼저 만들 것:** 한 지역·한 업종 검색, 식당별 두 백분위 비교, 잇플 상세 버튼.

**생각할 점:** 지역과 전국의 비교 집단 정의가 실제로 어떻게 되는지 확인해야 함. 매출 순위가 맛·만족도·재방문율은 아니고, 이 숫자만으로 `현지인 맛집`이나 `숨은 맛집`이라고 부를 수 없음. [공식 스킬 설명](https://github.com/NomaDamas/k-skill/blob/main/bccard-eatpl-search/instruction.md)

## 5. 오늘의 식당 정찰대

[80억분의 1](https://1in8billion.world/ko/)처럼 짧게 상황을 고르고 결과를 보는 웹게임 방식임. `오늘은 혼자 / 여럿`, `늘 먹던 업종 / 새로운 업종`, `직접 고른 동네` 정도를 선택하면 그 조건을 정리한 정찰 카드가 나옴. 사용자가 업종을 확인하고 검색하면 실제 식당 후보가 뜨고, 잇플 상세로 연결됨.

결과 카드에는 `오늘은 익숙한 동네의 새로운 업종 정찰` 같은 문구와 강아지·고양이 대원을 붙일 수 있음. 결과를 공유할 때는 가게 정보를 꾸며내지 않고 **선택한 조건**만 공유함.

**재밌는 점:** 설치 없이 짧게 시작할 수 있고, 메뉴를 못 정했을 때 출발점이 생김.

**먼저 만들 것:** 선택지 3개, 결과 카드, 사용자가 확인하는 지역·업종 검색.

**생각할 점:** `혼밥 가능`, `여럿이 앉기 좋음` 같은 식당 특성은 데이터가 없으면 판정하면 안 됨. 결국 결과가 일반 검색과 똑같으면 게임을 거칠 이유도 없음.

## 6. 강아지 vs 고양이, 오늘의 식당 대결

두 캐릭터가 같은 동네의 서로 다른 업종을 하나씩 골라옴. 사용자는 `강아지의 한식`과 `고양이의 중식` 중 하나를 고르고, 선택한 업종의 실제 식당 목록을 확인함. 마음에 안 들면 둘 다 넘기고 직접 검색할 수 있음.

**재밌는 점:** 메뉴를 정하기 어려울 때 두 선택지로 부담을 줄여줌. 캐릭터는 가볍게 분위기를 살리는 역할.

**먼저 만들 것:** 캐릭터 2개, 사용자가 고른 지역, 서로 다른 업종 2개, 검색 결과.

**생각할 점:** 실제 반려동물 동반 가능 식당을 알려주는 기능은 아님. 단순 양자택일은 기존 식당 선택 게임도 많아서 이것만으로 서비스 전체를 만들기보다는 다른 후보의 입구로 붙이는 편이 나을 듯. 예를 들면 [Choos](https://getchoos.com/)도 선택지를 줄여 식당을 고르는 게임을 제공함.

## 7. 점심 항로 — 갈 수 있는 곳부터 고르는 지도

점심시간이 짧아서 새로운 곳을 찾아보기 귀찮을 때 쓰는 방식임. 사용자가 직접 갈 수 있는 동네나 골목을 2~3개 고르고, 각 구역에서 먹고 싶은 업종을 선택함. 구역별 잇플 검색 결과 중 마음에 드는 가게를 고르면 오늘의 항로가 완성됨.

예를 들어 `학교 앞 골목 / 역 쪽 골목`을 직접 선택하고 `한식 / 중식`을 고른 다음, 각 구역에서 나온 후보를 비교함. 다녀온 구역은 본인이 직접 칠하고, 아직 안 고른 골목은 다음 식사 때 다시 볼 수 있음.

**재밌는 점:** 무작정 지도를 채우는 게 아니라 오늘 갈 수 있는 범위에서 새 선택지를 발견할 수 있음. 항로가 쌓이면 영토전으로 확장하기도 좋을 듯함.

**먼저 만들 것:** 직접 고른 구역 2곳, 업종 선택, 구역별 검색 결과, 상세 버튼. 처음에는 실제 지도가 없어도 구역 카드로 보여줄 수 있음.

**생각할 점:** 주소 검색만으로 반경이나 도보 시간을 계산할 수 없음. `걸어서 5분`은 별도 경로 정보 없이는 표시하면 안 됨. 구역을 여러 개 고르는 게 오히려 번거로울 수도 있으니 일반 검색과 비교해 봐야 함.

## 8. 식당 정보 블라인드 — 숫자의 정체 맞히기

같은 업종의 가게 두 곳에서 **실제로 제공되는 결제 매출 백분위**를 보여주고, 두 숫자 중 어느 쪽이 매출 순위가 더 높은지 맞혀보는 짧은 퀴즈임. 고르면 `상위 3%가 상위 20%보다 매출 순위가 높음`처럼 의미를 풀어주고, 두 가게의 이름과 잇플 상세를 보여줌. 숫자가 없거나 비교 집단이 확인되지 않으면 해당 문제는 만들지 않음.

예를 들어 같은 검색 조건의 가상의 A·B를 놓고 `상위 3% vs 20%`를 보여주는 식임. 정답 공개 후에는 한쪽을 자동 추천하지 않고 둘 다 살펴보거나 다시 검색할 수 있음.

**재밌는 점:** 카드 데이터가 단순한 장식이 아니라 탐색을 시작하는 계기가 됨. 사진과 후기보다 숫자부터 보는 재미도 있음.

**먼저 만들 것:** 가상 데이터 2개로 만든 한 문제, 숫자 설명, 결과에서 가게 선택. 실데이터는 사용 권한과 비교 기준 확인 후 연결.

**생각할 점:** 매출이 높은 곳이 더 맛있다는 퀴즈가 되면 안 됨. 문제를 풀고도 식당을 찾을 이유가 없을 수 있고, 같은 조건의 비교 가능한 자료를 충분히 받을 수 있을지도 미확인임. 식당끼리 직접 비교해 평가하는 [Vota](https://vota.org/en/guides/what-is-vota)도 있어서, 퀴즈 자체가 새로운 방식이라고 보기 어려움.

## 9. 같이 채우는 제철 식탁

친구들과 한 달에 한 장씩 제철 식탁을 채우는 방식임. [이달의 식재료](https://www.nongsaro.go.kr/mfood/kfi/foodMonth/list?dtlCode=3&menuId=PS03924&month=11&tabCode=1)에서 재료를 고르고, 각자 먹고 싶은 음식과 동네를 정해 관련 업종의 식당을 찾음. 먹은 뒤에는 직접 `먹었음`을 표시해서 식탁의 빈칸을 채움.

예를 들어 한 사람은 배추가 들어간 음식을, 다른 사람은 같은 달의 다른 재료를 고를 수 있음. 함께 같은 가게를 갈 필요 없이 서로 뭘 골랐는지 식탁에서 볼 수 있음. 강아지·고양이는 빈칸을 안내하는 캐릭터로 붙이면 좋을 듯.

**재밌는 점:** 영토를 뺏는 경쟁 대신 같은 목표를 함께 완성하는 방식이라, 가까이 살지 않는 친구끼리도 참여할 수 있음. 매달 식탁 주제가 바뀜.

**먼저 만들 것:** 이달 식재료 3개, 한 사람이 직접 음식과 동네를 선택하는 화면, 관련 업종 검색, 직접 완료 표시. 함께 보는 기능은 이후에 추가.

**생각할 점:** 특정 식당의 제철 메뉴 판매 여부는 별도 확인이 필요함. 친구들이 기록하려고만 들어오고 식당 검색은 이용하지 않을 수도 있음. 공동 식탁을 여러 기기에서 보려면 저장 방식과 운영 비용도 따로 정해야 함.

## 10. 언인스타 맛집 — 사진보다 밥

인스타에 올릴 만한 사진보다 **오늘 편하게 밥 먹을 곳을 찾는 경험**에 집중하는 서비스임. 화려한 사진을 앞세우는 대신 동네와 업종을 고르면 가게 이름, 주소, 확인 가능한 BC카드 결제 기반 지표를 담백하게 보여줌.

예를 들어 `신촌 → 한식`을 고르면 사진 피드 대신 식당 목록이 나옴. 각 카드에는 `지역 매출 상위 5%`처럼 실제로 제공된 숫자의 뜻과 기준 기간을 함께 표시하고, 궁금한 가게를 누르면 잇플 상세로 이동함. 매출 정보가 없으면 `정보 없음`으로 표시함. 메뉴·가격·영업시간은 실제 제공되는 경우에만 보여줌.

화면은 영수증, 주문서, 동네 밥집 메뉴판 같은 느낌으로 만들면 어떨까 싶음. 복잡한 후기 대신 `오늘 밥 어디서 먹지`에 바로 답하는 쪽임. 캐릭터를 넣는다면 앞치마 입은 강아지나 고양이가 메뉴판을 건네는 정도로 가볍게 넣을 수 있음.

**재밌는 점:** 인스타 스타일을 단순히 싫어하는 서비스가 아니라, 사진을 보느라 비교하기 어려웠던 사람에게 빠른 선택 화면을 제공한다는 점이 핵심임.

**먼저 만들 것:** 지역·업종 선택 → 식당 카드 3개 → 결제 지표와 정보 없음 표시 → 잇플 상세 이동. 정보는 먼저 가상 데이터로 구성함.

**생각할 점:** 잇플 데이터만으로 인스타에서 안 유명한 곳, 광고 안 한 곳, 현지인 단골집, 가성비 좋은 곳인지 판단할 수 없음. 결제 매출 순위도 맛이나 만족도를 뜻하지 않음. 인스타 감성을 피하는 것은 **가게의 성격을 판정하는 기준이 아니라 우리 서비스의 화면과 선택 방식**으로 잡는 게 현실적임.

해외에는 실제로 [사진을 찍기 어렵게 어두운 공간을 만들거나](https://www.foodnavigator.com/Article/2020/02/18/Futureproof-recipes-Instagram-unfriendly-restaurants-and-sober-bars-new-consumer-trends-identified/) [촬영을 제한하는 식당](https://www.restaurantonline.co.uk/Article/2024/12/13/why-are-more-restaurants-banning-photos/)을 `anti-Instagram` 사례로 소개한 적이 있음. 우리가 생각하는 건 촬영 금지 식당을 찾는 서비스라기보다, 식당을 고르는 화면에 그 감성을 가져오는 아이디어임. 이 이름의 특정 기존 서비스가 있는지는 확인하지 못함.

## 한국에서 요즘 볼 만한 사례

- **[80억분의 1](https://1in8billion.world/ko/):** 2026년 10월 등장한 국내 개발 웹 인생 시뮬레이션. 선택과 결과를 보며 플레이하고, 결과가 커뮤니티와 방송으로 퍼진 사례임. 국내 트래픽 순위나 이용자 수는 별도로 확인하지 못함. [보도](https://www.gameple.co.kr/news/articleView.html?idxno=216666)
- **[푸망](https://poomang.com/search):** 다양한 짧은 테스트를 모아둔 국내 서비스. 선택 후 바로 결과를 보는 흐름은 참고할 만함. 2020년 설립된 회사의 서비스라 신생 사이트 사례는 아니고, 사이트에 표시된 콘텐츠별 수치는 순 사용자 수로 확인되지 않음. [기업 정보](https://thevc.kr/poomang)
- **[MetaBot.GG](https://metabot.gg/en/TFT):** 국내 제작 사이트는 아니지만, Similarweb의 2026년 9월 한국 `게임 기타` 분야에서 40위로 전월보다 58계단 상승함. 게임의 여러 선택지를 통계로 비교하는 방식이 식당 비교 화면에 참고할 만함. [국내 분야별 순위](https://www.similarweb.com/top-websites/korea-republic-of/games/games/trending/)
- **[Wplace](https://wplace.live/):** 2025년 나온 세계지도 픽셀 놀이. 함께 한 지도에 흔적을 쌓는 방식이 영토전과 닮음. 당시 서울 주변의 참여도 보도됐지만, 현재 국내 이용량은 확인하지 못함. [보도](https://apnews.com/article/345b5ca144417050ab5c455fa984643d)

## 뭐부터 해볼까?

**언인스타 맛집**을 별도 후보로 두고 **점심 항로**와 **동네 탐험 빙고**와 비교해 보면 좋겠음. 항로는 오늘 갈 구역에서 식당을 고르는 데 집중하고, 빙고는 새로운 선택을 해볼 이유를 만들어줌. 메뉴 도감과 영토전은 식사 후 다시 돌아올 이유로 붙일 수 있을 듯함. 카드 데이터가 중심인 후보로는 **식당 정보 블라인드**도 같이 살펴볼 만함.

다만 먼저 가상의 식당 몇 개로 화면을 만들어서 **항로나 빙고가 실제 식당 선택을 돕는지** 봐야 함. 유사한 탐험·도감 서비스가 이미 있으니 새로운 조합이라는 가설이지, 세상에 없는 서비스라고 확정할 수는 없음.

잇플은 검색 결과의 가맹점 상세 주소로 연결하는 흐름이 필요함. BC카드의 **개인 결제 내역**을 읽거나 결제로 방문을 인증할 수 있다는 근거는 아직 없고, 메뉴 판매 여부·지도 좌표·API 운영 및 데이터 보관 권한도 따로 확인해야 함.
