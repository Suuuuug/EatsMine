# 화면 검증 루프 (EatsMine)

**영수증 없으면 커밋 없음.** 화면을 바꾼 커밋에는 증거(캡처, 독립 점수, 클릭 순서 결과)가 남아 있어야 한다. 구현자가 매긴 점수는 자체 평가로 표시하고 독립 평가를 대신하지 않는다.

**강도는 변경 크기에 맞춘다**(hallmark "Lightweight by default, heavyweight on demand"): 문구 한 줄은 자가 점검과 캡처 한 장, 새 화면·흐름은 아래 전부.

## 1. 띄우기

- `npm run dev:web`(:3000). 이미 떠 있으면 재사용. API가 필요 없는 화면은 웹만 띄운다.
- 배포 주소가 생기면 배포 주소에서도 한 번 더 본다(지금은 없음).

## 2. 캡처

Playwright MCP로 같은 화면을 **390x844, 768x1024, 1440x900** 세 폭에서 전체 페이지 캡처한다. 상호작용 상태(시트 열림, 선택됨, 빈 상태)가 있으면 그 상태도 한 장씩.
- 저장: `.playwright-mcp/review/<화면>/v<N>-<폭>.png`(로컬 전용).
- 가로 넘침은 `document.documentElement.scrollWidth > innerWidth`로 숫자 확인.
- 구현자가 390px 캡처 한 장은 먼저 직접 본다. 잘림·겹침은 평가자보다 먼저 잡는다.

## 3. 독립 평가 (Codex, 2026-11-24 사용자 지시)

디자인 평가는 **Codex**(`codex-companion task --model gpt-6.1-sol`, 읽기 전용)에 맡긴다(사용자: "디자인 평가나 이런건 codex한테 맡기자"). 캡처 경로·기준 문서·코드 경로를 주고 이미지를 직접 열어 보게 한다. Codex를 못 쓸 때만 `.claude/agents/design-auditor.md` 서브에이전트로 대신한다. 평가자에게는 **무엇을 만들었는지(사실)와 캡처 경로만** 주고 "좋아졌다", 이전 점수 같은 판단은 주지 않는다. 바꿀 수 없는 제약(팀 토큰 색, 사용자가 요구한 요소)은 사실로 적어 감점 사유가 되지 않게 한다.

점수(각 10점): 선택 상태와 행동의 명확성, 정보 위계, 접근성, 화면 일관성, 문구(토스 라이팅), AI 티 없음, 종합. **휴대폰(390)과 PC(1440)를 따로** 매긴다(skku-notice-platform 방식). 768은 넘침·깨짐만 본다.

## 4. 고치고 다시 (종합 8점까지)

- 휴대폰·PC 어느 한쪽이라도 종합 8 미만이면 지적을 고치고 2부터. 매번 **새 평가자**(같은 평가자는 자기 의견에 고정된다).
- 평가자끼리 반대를 요구하면 다수결이 아니라 기준 순서(사용자 지시 > 팀 토큰 > DESIGN.md > toss-ux-writing)로 정하고 이유를 기록한다.
- 사용자에게 중간 화면을 "다 됐다"고 하지 않는다. "N차 평가 몇 점, 무엇을 고치는 중"으로만.

## 5. 클릭 순서 (ui-evaluator)

정적 점수는 동작을 못 본다. `ui-evaluator` 서브에이전트가 실행 중 화면에서 사람 순서대로 누른다: 마우스 클릭, 키보드(Tab·Enter·Space·Esc, 이동 뒤 포커스 위치), 터치 폭 390. 바뀐 상태가 다른 곳(요약 문장, 목록)에 바로 반영되는지, 새로고침 뒤 유지되는지(로컬 저장이면). 잇플 링크는 도메인 차단 상태에서만 누른다.

## 6. 영수증

`docs/design/review-log.md`에 한 줄: 날짜, 화면, 판 번호, 캡처 경로, 점수 흐름(예: 7.1 → 7.8 → 8.3), 주요 지적, 남긴 것과 이유, 클릭 순서 범위, 못 본 것(실기기, 로그인 상태). daily-log와 커밋 본문에 "검증: 독립 평가 N점, 클릭 순서 M단계"를 남긴다.
