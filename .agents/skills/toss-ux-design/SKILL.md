# 토스 UI·UX 설계 기준 (EatsMine)

화면을 "예쁘게"가 아니라 **손과 눈이 덜 움직이게** 만든다.

## 1. 설계 전에 흐름을 센다

목표까지 사용자가 하는 일을 **클릭, 스크롤, 입력, 화면 전환**으로 작업 계약에 적고 줄인다.
1. 없앨 수 있는 단계(확인만 하는 단계, 다시 눌러야 하는 "다음")를 지운다.
2. 한 번에 끝나는 선택은 바로 반영한다. 되돌릴 수 없는 일만 화면 안에서 한 번 더 묻는다.
3. 다음 조작은 눈이 가 있는 자리 근처에서 끝난다. 누른 줄 **바로 아래**에 펼치고, 닫기는 제목 줄에 둔다.
4. 결과를 "클릭 N번, 스크롤 N번"으로 기록하고 바뀌면 이유를 말할 수 있어야 한다.

## 2. 화면 하나의 구조

- **한 화면에 일 하나.** 화면 제목 아래 부제는 두지 않는다. 설명이 필요하면 구역 제목 바로 아래 한 줄, 구역마다 최대 하나.
- **주 행동은 하나**, 엄지가 닿는 아래쪽에. 같은 뜻의 버튼을 위아래에 두 번 만들지 않는다.
- 같은 말은 한 곳에 한 번. 구역 제목과 행 이름이 같으면 제목을 줄인다.
- 눌리는 곳은 눈에 보이게: 행마다 경계(1px 선 또는 면)로 한 항목의 끝을 보이고, 높이 44px 이상(글자 링크도 `min-h-11`).
- 선택 상태는 색만으로 알리지 않는다(스위치 `role="switch"`+`aria-checked`, 글자 변화).
- **고르기만 하는 줄**(스위치)과 **이동하는 줄**(오른쪽 꺾쇠)을 한 묶음에 섞지 않는다.
- 왼쪽 세로줄로 하위 항목을 묶지 않는다. 하위 설정도 같은 묶음의 한 줄로, 이름만 읽어도 뜻이 통하게.

## 3. 목록·설정 묶음

- 마이페이지·설정 홈은 **들어가는 줄**의 묶음이다. 독립 기능(영토, 도감)은 자기 화면을 갖고 여기에는 줄 하나만 둔다.
- 먼저 할 일이 위, 그에 의존하는 설정이 아래. 켜야 의미 있는 설정은 스위치를 켠 뒤 펼친다.
- **막힌 조작은 이유를 말한다.** 비활성으로만 두지 말고 풀리는 조건을 쓴다("로그인하면 바꿀 수 있어요").
- 같은 종류의 입력·행은 같은 컴포넌트로. 화면마다 새로 만들지 않는다.

## 4. 눌리는 것은 모두 같은 반응

눌리는 요소(버튼, 줄, 스위치 줄, 링크 줄)는 화면과 상관없이 같은 기본 반응을 갖는다: 마우스 올림 `[@media(hover:hover)]:hover:bg-foreground/5`, 누르는 동안 `active:bg-foreground/10`, 키보드 포커스 `focus-visible:outline-2 focus-visible:outline-accent`(팀 Button과 같은 윤곽선). 부모 선택자에 기대지 말고 그 요소 클래스에 직접 쓴다.

## 5. 패턴은 오픈소스에서 먼저

새 패턴은 우리 스택(React + Tailwind v4)에 맞는 오픈소스에서 찾는다. 기준은 shadcn/ui(MIT, 복사 방식)의 Item·Switch·Field 구성이고, 구조만 가져와 팀 토큰으로 옮긴다. 문서는 context7로 확인한다. 의존성을 새로 추가하기 전에는 묻는다.

## 6. 점검 순서

1. 흐름을 센다(1번).
2. 휴대폰(390)과 PC(1440)에서 직접 눌러 본다. 키보드 Tab 순서도.
3. `ui-review-loop`로 휴대폰·PC 각각 독립 평가 8점 이상.
4. 결과를 있는 그대로 보고한다. 평가 전이면 "평가 전", 재평가 안 했으면 "재평가 안 함".
